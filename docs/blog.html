Publish an article people can explore.

A shared document powers the reading experience, visual editor and AI authoring tools.

Write and publish

Open Studio and sign in with an invited GitHub account. Add text, headings, layouts, media, galleries, code, YouTube, browser experiments, surveys or Clark widgets. Translate the English and Vietnamese versions, save, then preview the saved revision. Drafts and their uploaded media stay private.

Editors can read and write. Publishers can also publish both languages together, unpublish, and restore a previous publication from History. Loading an old revision as a draft preserves newer history. The owner invites numeric GitHub user IDs and can disable membership. Concurrent changes return a conflict without overwriting the newer revision; preserve your local changes before reloading.

Connect AI tools

The website endpoint is https://clarkcant.cc/mcp, separate from a personal Clark runtime. Add it as a remote MCP connector in a client supporting Streamable HTTP and OAuth with PKCE. Sign in and grant only needed scopes: blog:read, blog:write, blog:publish. Access expires after one hour; reconnect when needed.

ChatGPT and Claude are the intended OAuth clients. Real account consent remains dependent on deployment OAuth configuration and end-to-end verification. Protocol tests alone do not establish compatibility with those clients. Public Gemini buttons copy a prompt and open Gemini for the reader to paste it.

REST and CLI

OpenAPI describes typed operations. POST JSON to /api/blog/<operation> with a bearer token created in Studio → Connections & team. Tokens are displayed once, expire, and can be revoked there. The CLI never persists credentials.

corepack pnpm cli get_block_catalog --url https://clarkcant.cc
corepack pnpm cli list_articles --file query.json
corepack pnpm cli save_article --file article.json

Run from the website checkout. Set CLARKCANT_BLOG_TOKEN in the invoking process, or pass --api-key. Without a file, input comes from stdin. Output is JSON; failures exit nonzero.

Operations: list_articles, get_article, get_block_catalog, validate_article, save_article, publish_article, unpublish_article, article_history. Discover document schemas and exact widget versions before authoring. Save requires the revision you read and a unique retry key. Reuse the key with identical input after a lost response; different input needs a new key.

Interactive boundaries

Widgets use Clark's canonical built-in renderer, local view state and static article data. They cannot call a personal runtime or approve actions. Each widget needs a readable explanation and, where relevant, underlying data. Marketplace installation is a future extension, not enabled here.

Experiments start on Run in an opaque sandbox without network access or host credentials. Stop removes the frame. Browser sandboxing does not impose a CPU time limit: publish reviewed code. Surveys store anonymous answers with the article revision; editors can view totals. A rotating visitor hash supports rate limits; raw IP addresses are not stored.

Search and agent reading

Public articles render semantic HTML without JavaScript and expose .md versions. Copy Markdown copies the published content. AI buttons open the service and copy an article prompt; they do not automatically send content. Canonical URLs, language alternates, BlogPosting data, RSS, sitemap and llms.txt describe published content only. Interactive blocks retain explanatory text and data.
